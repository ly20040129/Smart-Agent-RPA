## 1. 项目背景

### 1.1 这是什么

电商客服每天要在「网店管家」ERP 里人工审核几百个订单：确认能不能发货、从哪个仓发、用哪个快递、要不要补赠品。本模块是这套人工审核的**自动化决策引擎**，输出一份《审核清单》Excel，交给影刀 RPA 去管家系统里批量执行「审核通过 + 改仓库 + 改快递」。

### 1.2 业务链路

```
网店管家导出订单报表(Excel)
        +
总库存表(Excel)  +  仓库快递对接表/机型表(Excel)
        ↓
order_judge.py  （本模块）
        ↓
audit_result.json + 审核清单.xlsx（可审清单 / 不审 / 规则清单 三页）
        ↓
影刀 RPA 读取 → 在网店管家里自动审核
        ↓
人工处理「不审 / 疑问 / 待定」队列
```

### 1.3 核心原则（最重要，任何改动都不能违背）

> **宁缺勿错。** 任何拿不准的订单都进「待定」或「疑问」队列等人工处理，
> 绝不能因为规则放宽而把不该发的单自动审核发出。

用户在 11-13 明确重申：**「能过的尽量过，不能的就别动」「能匹配得上有逻辑性处理的才加入，不然最好别加」**。
→ 不要为了凑数字硬加规则；找不到逻辑依据的特征就不要写成规则。

## 2. 运行方式

### 2.1 命令行

```bash
python order_judge.py <订单报表.xlsx> <总库存.xlsx> <仓库快递对接.xlsx> <输出目录>
```

示例：

```bash
python order_judge.py 订单11-13.xlsx 总库存1.xlsx 仓库快递对接.xlsx out_1113
```

运行成功后控制台输出：

```
[SUCCESS] 审单完成
  可审 N 单
  待定 N 单
  疑问 N 单
  输出: <输出目录>
```

### 2.2 依赖

- Python 3.8+
- `openpyxl`（读写 Excel）
- 无其他第三方依赖（库存/订单读取都用 openpyxl，不依赖 pandas）

### 2.3 输出文件

| 文件 | 说明 |
|---|---|
| `audit_result.json` | 结构化结果，含 queues / deferred / question，RPA 可直接消费 |
| `审核清单.xlsx` | 业务可读版本，3 个 sheet 见下 |

**审核清单.xlsx 的 sheet：**

| sheet | 内容 |
|---|---|
| `可审清单` | 能自动审核的单，含建议仓库、建议快递、是否需改仓改快递、赠品、备注 |
| `不审` | 规则拦截的单（退款/延期/刷单/无编码等），含拦截原因 |
| `规则清单` | 规则说明书（R01~R36）+ 第二页「待业务确认」问题列表 |

## 3. 输入文件格式

### 3.1 订单报表（用户每天从网店管家导出）

单 sheet 合并格式，一行 = 一个明细行。关键列：

| 列名 | 说明 |
|---|---|
| 分销单号 / 原始单号 / 订单号 | 分组依据（见 §5.1） |
| 店铺名 | 含「跨境/国际」= 跨境单 |
| 订单状态 | 只处理「待审核」 |
| 货品摘要 | 商品标题 |
| 货款合计 | 订单金额 |
| 仓库 / 物流方式 | 管家里的原值，代码可能改 |
| 客服备注 | 含延期、指定快递、赠品等信息 |
| 标记 | 如「退货仓新机」「今天一定发出」 |
| 退款状态 | 含「退款」= 整单退款 |
| 货品总数 / 订单拆分合并 | 11-12 起新增；「合并」= 空壳单跳过 |
| 编号 | 货品编码，格式 `1.319` / `2.225` / `04.xxx`（**无前导 0**） |
| 数量 | 明细数量 |
| 品名 | 库存表匹配用的完整品名 |
| 收件人 / 登记时间 | 辅助分析用（当前未参与规则） |

### 3.2 总库存表

多仓库存，关键字段：仓库、货品编号、品名、库存量、不良品、待发量。
**注意：库存表的编码格式是 `01.319`（带前导 0），和订单表 `1.319` 不一致 —— 见 §5.2。**

### 3.3 仓库快递对接表（机型表）

两张 sheet：`仓库快递对接`（仓→快递映射）+ `机器发货仓`（机型→仓）。
- 机型匹配用 token 匹配（如 667/664/621CW → 合捷仓）
- 表内末行可能有备注，匹配时要忽略

## 4. 规则清单（R01 ~ R36）

### 4.1 拦截进「待定」deferred

| 规则 | 条件 | 动作 | 来历 |
|---|---|---|---|
| **R25 整单退款** | 退款状态含「退款」 | 待定 | 11-11 新增 |
| **R03 延期发货** | 备注含 延迟/延期/等通知/先不发/暂不发/X号发/到货审；含「可以发/能发/正常发」则解除 | 待定 | 11-11 |
| **R04 暂停发货** | 备注含 先不发/暂不发/说不发 | 待定 | — |
| **R02 权益/预约/补差价** | 明细无编码 + 摘要/备注含 预约/权益/补差价/补运费/单拍不发货 | 待定 | 11-11 |
| **R21 刷单拦截（单笔）** | 独立单 + 货款=1 + 摘要含「打印」+ 明细编号全空 | 待定 | 11-06 |
| **R33 刷单族（批量）** | 同店铺 + 货款=1 + 备注空 + 摘要含「打印/办公」+ 订单号末4位连续簇 ≥3 单 | 整簇待定 | 11-13 用户核定 A 方案 |
| **R27 已合并空壳单** | 订单拆分合并含「合并」 | 整单跳过 | 11-12 |
| **R36 仅赠品行且无主单** | 整组明细全 4.xxx + 货款=0 + 无主单 | 待定 | 11-13 新增 |

### 4.2 拦截进「疑问」question

| 规则 | 条件 | 动作 |
|---|---|---|
| **R20 退货仓新机** | 标记含「退货仓新机」：**有编码且原仓库有值 → 放行照审**；否则疑问 | 11-13 加豁免 |
| **R30 明细无货品编码** | 整组全无编码：**货款>100 且摘要含补差价/补邮费 → 放行**；**货款≤1 且摘要含机器/办公 → 放行**；其余疑问 | 11-13 收紧 |
| **R31 原物流为空** | 物流空：**有编码且原仓库有值 → 用默认快递放行**；否则疑问 | 11-13 加豁免 |
| **R32 库存表无记录** | 查不到该编码：**编码非空且原仓库有值 → 豁免放行并标注**；否则疑问 | 11-13 新增 |
| **R05/R06 缺货** | 机器/有价耗材目标仓可用量不足 | 疑问/不审 |
| **R26 耗材缺货替代品** | 缺货时同仓找「型号数字+品类+套装属性」一致的唯一有货编码 | 仅提示，不自动换 |
| **R11/R12 机型未配置/多仓冲突** | 机型表无匹配或命中多仓 | 默认深圳仓 + 深圳仓-韵达快递，标注 |

### 4.3 自动进「可审」

| 规则 | 条件 | 动作 |
|---|---|---|
| **R01 专票/发票单** | 仓库=发票仓-财务 或 摘要含「数电专票」 | 可审，仓固定发票仓-财务，快递保持原值 |
| **R10 机器定仓** | 01/1. 开头机器行按机型表匹配 | 国内单：深圳仓有货优先深圳仓，缺货才走机型表仓 |
| **R22 跨境单** | 店铺名含跨境/国际 | 直接按机型表仓（合捷仓 + 合捷仓顺丰）；与国内单按「分销单号=原始单号」配对 |
| **R13 机器快递** | 合捷仓 → 合捷仓顺丰；深圳仓/退货仓 → 深圳仓-韵达快递 | 按仓定快递 |
| **R14 耗材默认** | 非机器单 | 深圳仓 + 深圳仓-韵达快递 |
| **R15 耗材指定顺丰** | 备注含「指定顺丰」 | 深圳仓 + 顺丰（平湖标快） |
| **R02b 无编码但有货品** | 明细无编码但摘要真实 | 按摘要机型定仓，可审，不校验库存，标注待补编码 |

### 4.4 赠品处理

| 规则 | 条件 | 动作 |
|---|---|---|
| **R16 赠品识别** | 备注出现 硒鼓/碳粉/墨水/纸/筋膜枪/吸尘器/榨汁杯 等 | 按库存品名模糊匹配；数量按「2个/×2」解析，默认 1 |
| **R17/R29 赠品不唯一** | 匹配到多候选或零候选（如「墨水」64 个候选） | 主商品照审，赠品剔除并在「跳过赠品」列标注候选数 |
| **R18 赠品不重复** | 明细已含同项 | 不重复添加 |
| **R08/R09 赠品缺货** | 04 行缺货 | 剔除该赠品，主商品照审；整单仅赠品行则校验库存 |
| **R19 主子单** | 同分销单号或同原始单号多笔 | 每子单按自己货品定仓定快递；赠品只加主单 |

## 5. 关键实现细节 & 踩过的坑（必须保留）

### 5.1 分组 key 必须带店铺前缀 ⚠️

```python
# 正确：
key = (shop, id_key)   # id_key = 分销单号 or 原始单号 or 订单号
# 错误（会串单）：
key = id_key
```

**原因**：曾出现「添美办公跨境 0766（合捷仓）」和「淘宝睿彩办公 0785（深圳仓）」因为
分销单号=对方原始单号被错归成一组，导致 01.383 用深圳仓去查当然无记录。
加 shop 前缀后独立成组。

### 5.2 编码格式不一致：订单表 `1.319` vs 库存表 `01.319` ⚠️

这是 11-13 发现的最严重 bug：`available()` 永远查不到库存，**库存校验全部失效**。

修复方式（已在代码中）：

```python
def _code_variants(code):
    """兼容 1.319 / 01.319 两种格式"""
    c = str(code or "").strip()
    if not c: return ()
    v = {c}
    if re.match(r"^\d\.", c):    v.add("0" + c)   # 1.319 → 01.319
    elif re.match(r"^0\d\.", c): v.add(c[1:])     # 01.319 → 1.319
    return tuple(v)
```

`available()` 和 `find_substitute()` 都必须用 `_code_variants()` 兼容查询。

### 5.3 classify 前缀兼容 `1.` 和 `01.`

早期只认 `01.` / `02.` / `03.` / `04.`，但订单表实际是 `1.` `2.` `3.` `4.`（无前导 0），
导致所有机器单被当成 other、库存校验全跳过。修复：

```python
MACHINE_PREFIX   = ("01.", "1.")
CONSUMABLE_PREFIX= ("02.", "03.", "2.", "3.")
GIFT_PREFIX      = ("04.", "4.")
```

### 5.4 R28 超订拦截已删除

管家导出的「订购量/库存量」字段不可信（案例：1151 客户拍 9 台实际只发 1 台，订购量列残留 9）。
真正发多少看明细数量。**不要恢复 R28。**

### 5.5 R34「机器本身无编码」已撤回

曾经按「摘要含机器词 + 明细全是耗材编码」判疑问，结果误伤 37 单，已删除。

### 5.6 订单报表的「标记」「订单拆分合并」列管家不自动填

不能指望这两个字段区分刷单/合并单，只能靠行为特征（货款=1、备注空、订单号连续簇等）。

### 5.7 跨境单配对逻辑

跨境单和对应的国内单通过「分销单号 = 原始单号」配对。
配对后：跨境单走机型表仓（合捷仓），国内单只剩耗材 → 深圳仓+韵达，两单明细不合并。
